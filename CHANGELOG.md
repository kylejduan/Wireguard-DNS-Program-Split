# Changelog

## 0.3.3 - 2026-10-15

- Windows: after a reboot, selected applications reach the tunnel as soon as it is up. A shutdown keeps the persistent filters, NRPT rule and dispatcher, and the controller then starts only the tunnel; that path did not load the PIA callout driver, which nothing else starts after a boot, so the filters blocked selected applications until the first 30-second health check repaired them about 32 seconds later. The driver now loads alongside the tunnel start, and the whole stack is validated on the next two-second pass instead of after the full interval.
- Windows: adopting the stack at boot is no longer logged as a tunnel failure, and saves no health-failure evidence. One capture per boot had been pushing real failures out of the ten kept. A tunnel that then fails to start is still recorded as an outage.
- Windows: a physical DNS resolver that does not answer no longer keeps the tunnel from starting. The tunnel-only restart had held on the dispatcher's loopback probe, which needs the physical resolver, so selected applications stayed blocked for the whole resolver outage although an address endpoint needs no physical DNS. The tunnel now starts and the health check holds the stack; changed network inputs still take the full restart.

## 0.3.2 - 2026-10-15

- Windows: every script reads state files as UTF-8, matching how they are written. Windows PowerShell had read them in the ANSI code page, so a listed executable whose path has non-ASCII characters was corrupted on the next tray edit and lost its filters and DNS attribution.
- Windows: the installer never writes the WireGuard private key outside a protected directory. `-PlanOnly` validates the profile without writing it, and a real install stages under a directory restricted to SYSTEM and Administrators from creation, instead of the user's `%TEMP%` with the ACL applied afterwards. Staging left by an interrupted run is removed only when the directory and every file in it carry exactly the installer's security descriptor. Removal never follows a symbolic link, junction or hard link, and no longer overwrites before deleting, which could change a hard-linked file elsewhere and does not reliably remove data on SSDs or NTFS.
- Windows: a hostname endpoint that resolves through a CNAME now starts. Only A records are used, and a name without one gives a clear error.
- Linux: mark reservation is exact for every accepted rule. Legacy and iptables-nft `CONNMARK --restore-mark` reserves both `--nfmask` and the shifted `--ctmask`. `TPROXY --tproxy-mark` and nftables writes of the current mark with a constant `or`, `xor` or `and` are modelled exactly. iptables dumps are parsed rule by rule from unquoted keywords, so a quoted value such as a string-match pattern `"-j"` cannot hide a rule's real target, and comments with newlines or escapes and repeated arguments of other targets no longer block activation. kube-proxy, docker, ufw, firewalld, tailscale, fail2ban, libvirt and podman rulesets are accepted with their exact mark bits.
- Linux: targets are handled by allowlist. Besides MARK, CONNMARK and TPROXY, only chain jumps and targets known never to write the packet mark are accepted. Anything else, such as xtables-addons `IPMARK` or `HMARK`, is refused by name as a conflict, including when nftables shows it only as an opaque iptables-nft extension. `SET --map-mark` and `socket --restore-skmark`, which take a mark from mutable ipset entries or sockets, are refused. So are the iptables `TEE` target and nftables `dup` and `fwd` statements, since a copy of included traffic sent elsewhere would leak its plaintext. Packet queue verdicts remain accepted unmodelled, as an administrator responsibility.
- Linux: the owned egress chain enforces that included DNS leaves only for the profile resolver after all NAT. A foreign NAT chain or REDIRECT that ran earlier and sent port-53 traffic to the host stub or another resolver now has those queries dropped instead of answered, and the readiness probe fails closed. Foreign nftables rules that rewrite addresses or ports statelessly, which could move DNS past that guard before conntrack, are refused by name. Replies from an enrolled DNS server are not affected.
- Linux: the native performance harness validates each build's own installer launcher and cleans up a run that fails after installation.

## 0.3.1 - 2026-10-14

- Windows: a reader holding a component or probe log open no longer fails the check that writes it, which had stopped the tunnel and repaired the stack in a loop. Every program the components wait on now runs through `controller-service.exe --run`: created suspended and already inside its own job without breakaway, run only once containment is confirmed, with each argument quoted for it, ended with its descendants at a deadline counted from its own start however late its result is collected, both pipes drained with bounded retention and cancellable reads, and its output returned framed and base64-encoded so it is decoded by what each program writes. The log files are a best-effort copy.
- Windows: stuck tunnel-host recovery measures how long the host has been pending on the monotonic clock, keyed to the process ID and creation time, so a backward clock step no longer delays it and a forward one no longer ends a young host. The first sighting is kept by the controller and passed back to the tunnel component, so a state file that cannot be written does not reset it. The profile-import filter hold likewise runs its five minutes on the monotonic clock from the first sighting of the request.
- Windows: the dispatcher keeps up to three physical resolvers and passes over one that stops answering after 1.2 seconds, preferring the one that answered until the first is due a re-probe, a minute after it last failed, which steady traffic does not postpone. All upstream attempts for one query, over every resolver and both transports, share one four-second deadline, and the UDP fallback after TCP divides what is left between the resolvers. The dispatcher's direct-network snapshot takes its source address and resolvers from one chosen interface. The health check and the uplink hold count any answering resolver, so a dead primary with a live secondary is no longer an outage. The dispatcher inputs list the resolvers comma-separated and are validated strictly.
- Linux: a transient early-guard failure, such as `/run` briefly out of space, no longer leaves the controller unstarted. The controller unit now wants rather than requires the guard, retries a failed startup with backoff from 5 to 60 seconds, and runs the guard again first on each retry; disable stops the retries and boot is never stalled. Health checks read named routing tables once per observation instead of once per route.
- Linux: the controller reuses nftables and iptables-nft listings while the kernel's nf_tables ruleset generation is unchanged, analyses each distinct ruleset once, and skips empty legacy iptables dumps, halving steady-state controller CPU (11.9 to 5.9 ms per second on the reference VM) while still detecting any foreign nftables or iptables-nft edit at the next check. While any owner-bound nftables table exists, every listing is read fresh, because the kernel deletes such tables without advancing the generation.

## 0.3.0 - 2026-10-14

- Windows payload filters are now persistent WFP objects under a fixed project provider instead of a dynamic session owned by a long-running `wfp-probe.exe`. Selected applications therefore fail closed, instead of leaving on the physical route, when the filter tool or controller crashes, BFE restarts, the host boots before the stack is up, or a repair rebuilds the stack. `wfp-probe.exe install` replaces the whole set in one transaction, which an included-application reload and a profile import's new tunnel address now use instead of removing the filters first; `verify` runs with the 30-second health checks, and a mismatch or unregistered PIA callout is reinstalled in place; `remove` recovers a broken installation. Only the tray's Disable, a controller service stop and `Uninstall.ps1` remove the filters. Hard block filters in the top sublayer refuse a selected application's IPv4 whose local address is not the tunnel address, so fail-closed no longer depends on the PIA driver having registered its redirect callouts, and the same set blocks its non-loopback IPv6, so an IPv6 default route is no longer refused, and the uplink-outage hold now applies only to tunnel and transport failures. Boot-time copies of the blocks cover TCP/IP start until BFE loads the set. Without the driver, the redirect callouts alone were observed to let a listed program's traffic through; the blocks refuse it. Repairs and reloads no longer stop the dispatcher: it reads its inputs and the identity record from state files and reloads them in place on request, validating them first and keeping the loaded ones when they are invalid, and reports a reload generation. `controller-service.exe` supervises it independently of the controller's blocking work, restarting it about a second after it ends, and suspends the owned NRPT rule only when no dispatcher has been ready for 15 seconds, restoring it once one is. A listed executable that is uninstalled or being replaced no longer stops the stack: it is reported once and keeps its filters, keyed by an identifier derived from its path, so a restored copy is covered at once. `wfp-probe.exe` resolves every entry once (junctions, links, substituted drives; an absent file through its nearest existing ancestor, never past a link whose target cannot be opened) and records the result, which the dispatcher attributes by and validation compares with the filters; an entry that does not resolve keeps its recorded identity. A listed executable whose name has uppercase non-ASCII letters was never matched, because the management API lowercases only ASCII; it now also gets filters under its fully lowercased identifier. A reload during a provider outage keeps the dispatcher and NRPT rule and hands the tunnel to the tunnel-only restart. Each filter carries its entry's attribution identity, so filters recovered without the identity record still give the dispatcher a path, and an entry with identifiers but no path is refused. A selected application's DNS could go direct when an unlisted application had just looked up the same name, because its packet could be routed before its own ETW event was processed; every direct decision now waits for an ordering barrier, a sentinel event written through the dispatcher's own provider on the same session after the packet arrived, and is refused if the barrier does not complete. The session's periodic flush had failed with `ERROR_MORE_DATA` after its first call, so lost ETW events went undetected; it now passes a buffer large enough. The supervisor reconciles the NRPT rule with readiness on every pass, runs its PowerShell helper asynchronously, and republishes a lost dispatcher process ID; enabling the rule requires a ready dispatcher; and a reload rejects an identity record with any malformed row. Tunnel evidence now survives a newer unlisted event for the reuse window, so a selected retransmission or TCP fallback cannot go direct. A dispatcher that is alive but no longer answers a liveness query is replaced. An unresolvable entry keeps the identifiers and attribution paths of both its committed filters and its record. A truncated upstream answer is completed over TCP on the same route and returned over UDP when it fits, and a direct answer is withheld when a selected lookup of the same name started while it was in flight, since the DNS Client would hand it that answer, or while ETW loss or overflow quarantine is active. A query event from a process that could not be identified now blocks direct routing and direct answers for that name for ten seconds. A profile import stops only the tunnel, keeping the dispatcher, NRPT rule and cache policy. A partly restored cache policy stays pending across a controller restart. An adopted dispatcher can be replaced when it hangs, and one that never publishes its inputs is replaced after ten seconds. Record parsing in the native tools no longer throws on overflow, and no exception can end the service host or escape a dispatcher thread. The installer refuses an aliased installation root. Removal reads no configuration. `wfp-probe.exe` enumerates only the project provider's objects. The two-second supervision pass reads the owned NRPT rule from the registry instead of CIM. Installing over an earlier release commits the new blocks before ending its running filter host. `Migrate-Installation.ps1` refuses an installation whose other scripts or binaries are not this release's. A new CI test exercises install, verification, atomic replacement, killed installs and removal against the real filter engine, and proves without the driver that a listed copy's IPv4 and IPv6 are refused while an unlisted copy is unaffected. Another kills the supervised dispatcher at random moments and checks DNS recovery, lane separation, reloads under load and the NRPT suspension.

- Linux resolver guard: a cached Unix stream label could outlive the binding or rename that made one of its ends a protected resolver socket. Tracing programs on `unix_bind`, `vfs_rename` and `/run/user` owner changes now advance the role generation after each effect is visible and before the system call returns. A SAFE label is stored only once the stream's peer is published, and a stream's role and generation are written as one 64-bit word. A rename into a slot holds the destination role only until the rename completes, for both participants of an exchange. A new guard caches nothing until every task present at attachment has exited or shown a kernel stack walk taken while it was not running and ending at a real stack bottom with no frame in either function, so a bind or rename in progress during the load cannot leave a stale cached label; the proof runs under one three-second deadline and rescans only the threads still pending, so a busy host publishes the guard unsettled instead of holding the load past the controller's command timeout; health checks retry it (`bpf-loader drain`), and `bpf-loader drain-report` shows how the walks end. The invalidating programs attach first and detach last. `guard_slots` and `endpoint_names` hold 1,024 entries, and a running guard loaded with the earlier 128-entry maps is adopted until the next load. A guard load interrupted midway is recovered from its staging directory and a birth record of its map and link identities, and a disable interrupted while removing pins resumes, removing only pins whose identities match. The controller journals network acquisition only after its empty receipt is durable. An interrupted initial acquisition is rolled back automatically, refusing changed or unrecorded resources. An interrupted repair keeps the firewall, policy rule and fallback route and is retried. SIGTERM wakes the health loop at once, ownership audits are rate-limited to once a minute, preflight invariants are cached, sysctls are read from procfs, and the conntrack inventory is streamed under a 15-second deadline. `tests/linux/test_label_model.py` checks the labelling protocol exhaustively over bounded interleavings, including interrupted loads and calls in flight at attach time.

- Reuse bounded Windows validation and Linux native observation workers while preserving fresh ownership checks and hard timeouts. Linux captures native output with streaming size limits and hashes each owned firewall snapshot once. Windows retains only received UDP request bytes, coalesces TCP DNS frame writes, disposes component handles and avoids redundant tray updates. The Windows worker trades additional resident memory for lower CPU; see the [follow-up audit and remaining opportunities](docs/performance.md#october-11-2026-broader-audit-and-implementation).

- Reduce Windows supervision CPU by querying process image paths without module enumeration, and reduce Linux firewall-inventory allocations. Exact process ownership, complete mark/zone validation and health-check intervals are preserved. See the [paired performance audit](docs/performance.md).

- Windows installs now default to `%ProgramFiles%\WireGuardProgramSplit`. Service and controller child commands support paths with spaces. `Migrate-Installation.ps1` moves an active legacy ProgramData installation with its configuration and permissions, updates services and the tray, and rolls back on activation failure.

- Windows tunnel startup now uses a single serialized creation path: the automatic controller starts the Manual tunnel service only after orphan-adapter preflight. Running/starting owned services are reused. Remaining enumerated root WireGuard devices or an existing split adapter block a new creation attempt; ambiguous devices are preserved. This closes the SCM automatic-start bypass of cleanup.

- Windows installation: after activation and every five minutes while enabled, inspect stray `ROOT\WIREGUARD` devices that Windows servicing can recreate. Remove at most one verified, disconnected device with zero traffic and no configured address or nonlocal route per pass. Recheck identity immediately before exact-device removal, preserve a diagnostic snapshot, and keep maintenance failures independent of VPN health/restarts. Software-enumerated tunnels and shared driver packages are preserved.

- Windows controller: a local split-DNS probe failure now holds the stack when the physical resolver itself is not answering, instead of failing the startup gate and retrying in a loop. The dispatcher answers unlisted names by forwarding them to that resolver, so when a LAN resolver stops responding the probe cannot pass however healthy this stack is; the previous behaviour aborted `Start-Stack` before the payload filters started and cycled, at one point leaving the NRPT rule pointing at a dispatcher that had been stopped, which fails every lookup on the host. The same condition is now also a hold reason in the periodic health path, and `Get-ProgramSplitPhysicalResolver` reports the forwarding resolver for both checks. A dead resolver observed in the field took the whole LAN's DNS down for about ten minutes and cost several restart cycles, each one a fail-open window for the selected applications.

- Windows controller: a periodic health failure while the host has no physical default route, source address or pre-dispatch resolver now holds the stack and retries instead of restarting it. Losing the uplink used to remove the payload filters and the NRPT rule, so selected applications could leave through the physical path while the tunnel could not work anyway; a gateway reboot produced seven such cycles over four and a half minutes. Validation still restarts the stack once the uplink returns with a different route, address or resolver.

## 0.2.0 - 2026-09-17

### Linux (new, experimental)

- Add the experimental Linux include mode: a BPF LSM classifier marks new IPv4 sockets of enrolled executable paths, kernel policy routing and nftables send them and their ordinary DNS through WireGuard, and unlisted programs keep host routing and DNS. See [docs/linux.md](docs/linux.md).
- Resolver guard file path: a regular file proved to have no resolver role is remembered in a bounded 65,536-entry cache keyed by inode identity and stamped with the guard configuration epoch, so ordinary opens and reads skip pathname matching; only single-link files whose names no built-in rule inspects are cached, a rename into a protected slot still labels the file first, and a second link or an enrollment change forces a recheck. Field reads on that path are direct instead of probe helpers, and name comparisons are branch-free. Policy ABI 4 adds the cache map: disable and uninstall with the old CLI before installing.
- Fix Linux guard semantics: label Unix streams again on first use after a generation change instead of re-resolving every message and refusing an included process's unrelated streams; classify tasks in private user namespaces normally; refuse only enrolled unlinked images so unlisted processes keep socket creation after a package upgrade replaces their binary; identify filesystems by the kernel's superblock device (btrfs subvolume roots) and verify the classification context at load time; match `nscd` cache parents and 63-byte slot names exactly.
- Harden the Linux loader and controller: guard loading tolerates cgroups that vanish mid-walk, verifies the BPF object inventory before pinning, publishes pins by atomic rename from a staging directory, never fails on user-writable runtime-directory content, and lets libbpf own the verifier log; the controller recovers pending edits from its health loop, survives transient errors, retries the DNS probe, observes the daemon's activation before competing for the lock, reports lock timeouts as such, resolves named routing tables, inventories iptables-nft mark and conntrack rules through their textual dumps, delivers included traffic to all local host addresses, and completes an explicit disable after a foreign ruleset flush.
- Record the reference-host end-to-end check: enrolled copies exit through the provider with provider DNS, unlisted programs keep the router path, and total included latency is set by the provider endpoint distance and DNS cache bypass, not by the classifier.

### Windows

- Windows health checks no longer restart the whole stack over one lost packet. `dns-probe.exe` takes an attempt count, retransmits the same query, uses a random query id and requires the reply to echo the question, ignores datagrams and ICMP resets that are not a reply to it, pauses before retrying a refusal or socket error, and reports `No DNS response after N attempts`, `DNS response rejected` and `DNS probe failed` separately (a timeout used to be reported as `Invalid DNS response`). The periodic tunnel probe, the startup local split-DNS probe and dispatcher validation use three attempts, as the Linux controller already did; the startup tunnel gate stays single-shot because its own loop retries. A restart leaves the included applications on the direct route until the stack is back, so an avoidable one is a privacy cost, not only an interruption.
- The Windows controller snapshots the component logs into `logs\health-failures\<time>` (the ten most recent are kept) before the restart that overwrites them, including logs a running component still holds open; a long-running log is kept as its last 2 MB.
- The Windows controller service also accepts pre-shutdown, which arrives before Windows starts ending processes, answers interrogate, and appends one line to `controller-service.log` saying which path ended it, written before it reports stopped.
- The tunnel start path clears a stuck stop within five seconds so that, when the service and adapter then come up promptly, reset plus the readiness wait stays inside the controller's 45-second component limit.
- Windows controller: keep supervising when an interactive disable cannot complete cleanup (record the failure in `last-error.txt` best-effort and retry with bounded backoff), retry service-stop cleanup for up to 150 seconds before reporting failure, log why a health check restarts the stack, and log a component's output even when it fails. The tunnel component issues non-blocking start and stop controls, reports a fast start failure at once, never terminates a young starting host (a slow start is adopted by the next attempt, including when stop runs as failure cleanup), and resets a host that has been starting for more than 90 seconds or a stop that exceeds 20 seconds by terminating only the owned, handle-pinned `tunnel-host.exe`. A stuck tunnel previously made the controller exit with code 1 on every disable, leaving SCM restarting it in a loop.
- Windows controller service: accept the shutdown notification and report a controller ended by system shutdown as a clean stop. Every restart and shutdown previously logged the service as failed with service-specific error 1 ("Incorrect function").
- Windows dispatcher: reuse the route of a name and type answered within the previous three seconds when a repeated query carries no new DNS Client attribution event, instead of answering `SERVFAIL`. Retransmissions and TCP fallback by the Windows DNS Client no longer fail; never-attributed queries still do.
- Replace the delayed startup controller task with an automatic, restartable Windows service.
- Wait for physical-route readiness without repair backoff and tolerate a tunnel-service `StartPending` race.
- Refuse to overwrite or uninstall same-name foreign scheduled tasks, services, or NRPT rules.
- Roll back both active profile files, after a stopped-controller acknowledgement, if a tray import fails.
- Preserve recovery backups across failed or repeated profile-import attempts.
- Reject duplicate WireGuard sections/required fields, invalid keys, and invalid endpoint ports.
- Preserve raw ETW performance-counter timestamps and flush actionable DNS failure diagnostics.
- Serialize installs and remove exact-owned profile staging left by interrupted runs.
- Serialize the dispatcher readiness message, detect late IPv6 defaults, and remove only exact-owned endpoint routes.

### Tests and CI

- Tests: tunnel recovery and controller health tests live in their own files, and `./tests/run.sh --live` runs the recovery functions against the real Service Control Manager using a throwaway service that hangs on purpose (elevation prompt; the installed tunnel is never touched).
- Add a Linux CI job for the unprivileged suite, a manual privileged disposable-VM job, and the guarded native overhead measurement harness.
- The Windows CI job also runs the tunnel recovery and controller health tests.
